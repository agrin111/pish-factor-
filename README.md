# Aghrin PishFactor — سامانه اختصاصی صدور پیش‌فاکتور شرکت آهن آگرین

سامانه عملیاتی و یکپارچه برای مدیریت مشتریان، کاتالوگ و قیمت‌گذاری کالاهای فولادی، صدور پیش‌فاکتور با شماره‌گذاری یکتا، تولید فایل PDF رسمی فارسی (A4)، گزارش‌گیری فروش و کنترل دسترسی مبتنی بر نقش.

این نرم‌افزار یک نمونه نمایشی نیست: احراز هویت، دیتابیس، محاسبات مالی، تولید PDF و کنترل دسترسی همه در سمت سرور اجرا و اعتبارسنجی می‌شوند.

---

## معماری و فناوری‌ها

| لایه | فناوری |
| --- | --- |
| Frontend | Next.js 15 (App Router)، React 19، TypeScript، Tailwind CSS v4، RTL کامل با فونت Vazirmatn |
| Backend | Server Actions و Route Handlers در Next.js، اعتبارسنجی با Zod، کنترل دسترسی در هر عملیات |
| Database | PostgreSQL 16 + Prisma ORM + Migration |
| Auth | ورود با نام کاربری/رمز عبور، هش `scrypt` با Salt تصادفی، Session مبتنی بر دیتابیس در کوکی `HttpOnly` |
| PDF | PDFKit + فونت Vazirmatn جاسازی‌شده + الگوریتم دوجهته (Bidi) و شکل‌دهی حروف فارسی |
| Deployment | Docker + Docker Compose (PostgreSQL، Migration خودکار، Next.js standalone) |

### چرا این معماری؟

- **PostgreSQL + Prisma** برای صحت داده مالی: مبالغ با `Decimal(18,2)` ذخیره می‌شوند و نه Float.
- **Session در دیتابیس**: غیرفعال‌کردن کاربر یا تغییر رمز، فوراً همه نشست‌های او را باطل می‌کند — چیزی که JWT بدون لیست سیاه نمی‌دهد.
- **Server Actions**: همه عملیات نوشتن در سرور اجرا و دوباره اعتبارسنجی می‌شوند؛ رابط کاربری فقط نمایش است.
- **PDF سمت سرور**: فایل نهایی مستقل از مرورگر، با فونت جاسازی‌شده و نمایش صحیح حروف پیوسته فارسی تولید می‌شود.

## ماژول‌های پیاده‌سازی‌شده (فاز اول — MVP)

1. **ورود و نقش‌ها** — مدیر سیستم و کارمند فروش، محدودیت تلاش ناموفق ورود، ثبت ورود/خروج در Audit Log.
2. **داشبورد** — تعداد کل، امروز، در انتظار پاسخ، تأییدشده، لغوشده، منقضی‌شده، مجموع مبالغ، نمودار ۶ ماه اخیر، آخرین اسناد و مشتریان. وضعیت «منقضی‌شده» بر اساس تاریخ اعتبار محاسبه می‌شود.
3. **مدیریت مشتریان** — ثبت، ویرایش، جستجو با نام/موبایل/شرکت، حذف با کنترل وابستگی پیش‌فاکتورها.
4. **مدیریت کالا** — کد یکتا، دسته‌بندی، مشخصات فنی، سایز، ضخامت، طول، واحد، وزن، قیمت، فعال/غیرفعال.
5. **صدور پیش‌فاکتور** — شماره‌گذاری اتمیک (`AG-1405-0001`)، انتخاب مشتری، ردیف از کاتالوگ یا ردیف دلخواه، Snapshot مشخصات و قیمت کالا، هزینه حمل، تخفیف، مالیات اختیاری، مبلغ به حروف، ذخیره پیش‌نویس و ثبت نهایی.
6. **PDF رسمی A4** — سربرگ با لوگو و اطلاعات شرکت، مشخصات خریدار/فروشنده، جدول کالاها با شکست صفحه، خلاصه مالی، مبلغ به حروف، شرایط، سلب مسئولیت، محل مهر و امضا.
7. **آرشیو و جستجو** — جستجوی شماره/مشتری/موبایل، فیلتر وضعیت، بازه تاریخ شمسی، فیلتر صادرکننده، کپی سند، تغییر وضعیت با تاریخچه، حذف با کنترل نقش.
8. **تنظیمات شرکت** — لوگو، تماس، نشانی، شناسه ملی، کد اقتصادی، اطلاعات بانکی، واحد پول، مالیات و شرایط پیش‌فرض، پیش‌شماره شماره‌گذاری، متن سلب مسئولیت.
9. **کاربران و Audit Log** — ایجاد/ویرایش کاربر، تغییر نقش، غیرفعال‌سازی فوری، تغییر رمز، مشاهده فعالیت‌ها.
10. **گزارش‌ها** — گزارش بازه‌ای، ماهانه، مشتریان، عملکرد کاربران، اسناد؛ خروجی CSV سازگار با Excel (با BOM فارسی). کارمند فروش فقط اسناد خود را می‌بیند.
11. **پشتیبان** — خروجی JSON کامل از داخل نرم‌افزار + راهنمای `pg_dump`/`pg_restore`.

## اجرای محلی

```bash
npm install
cp .env.example .env     # سپس مقادیر را تنظیم کنید
```

### ۱. دیتابیس محلی

اگر PostgreSQL نصب دارید، `DATABASE_URL` را به آن تنظیم کنید. در غیر این صورت یک PostgreSQL موقت بدون نصب سیستمی اجرا کنید:

```bash
npm run db:dev
# در ترمینال دیگر:
# DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:5433/pishfactor?schema=public"
```

### ۲. ساخت جداول و داده اولیه

```bash
npx prisma migrate deploy
npm run db:seed            # یا: SEED_DEMO=1 npm run db:seed برای داده نمایشی
```

### ۳. اجرا

```bash
npm run dev      # http://localhost:3000
```

### ۴. تست و بررسی

```bash
npm test         # تست‌های محاسبات مالی، تاریخ شمسی و PDF
npm run lint     # بررسی TypeScript
npm run build    # ساخت نسخه تولیدی
```

## ساخت اولین مدیر سیستم

حساب مدیر اولیه هنگام `npm run db:seed` با مقادیر `SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` ساخته می‌شود (پیش‌فرض `admin` / `Aghrin@1404`).

برای ساخت یا بازنشانی مدیر در هر زمان:

```bash
npm run admin:create -- admin 'Ramz-e-Ghavi-1405' 'مدیر سیستم'
```

پس از اولین ورود، رمز عبور را از بخش **کاربران و لاگ فعالیت → رمز عبور** تغییر دهید.

## امنیت و کنترل دسترسی

- رمز عبور با `scrypt` (N=16384, r=8, p=1) و Salt تصادفی ذخیره می‌شود؛ رمز خام هرگز ذخیره یا ثبت نمی‌شود.
- Session با شناسه تصادفی ۳۲ بایتی ساخته و فقط **هش SHA-256** آن در دیتابیس ذخیره می‌شود.
- کوکی نشست `HttpOnly`، `SameSite=Lax` و در تولید `Secure` است؛ Server Actions علاوه بر آن، مبدأ درخواست را بررسی می‌کنند.
- هر Server Action و Route Handler مستقلاً نقش و مالکیت سند را بررسی می‌کند (کارمند فروش فقط اسناد و مشتریان مجاز خود را می‌بیند).
- همه محاسبات مالی در سرور بازمحاسبه می‌شوند؛ مقادیر ارسالی کلاینت معتبر نیست و تفاوت آن‌ها نادیده گرفته می‌شود.
- ورودی‌ها با Zod و محدودیت طول اعتبارسنجی می‌شوند؛ دسترسی دیتابیس از طریق Prisma و کوئری پارامتری است (بدون SQL Injection).
- خطاهای سیستم فقط پیام عمومی فارسی به کاربر نشان می‌دهند؛ جزئیات به لاگ سرور می‌رود.
- عملیات مهم (ورود، تغییر وضعیت، حذف، تغییر قیمت، تغییر رمز، پشتیبان) در `AuditLog` ثبت می‌شوند.
- حذف مشتری دارای پیش‌فاکتور و کالای استفاده‌شده در اسناد مسدود است (کنترل وابستگی با Foreign Key).
- شماره پیش‌فاکتور با `UPDATE ... RETURNING` داخل تراکنش تولید می‌شود؛ قید `UNIQUE` روی شماره محافظ دوم است.

## شماره‌گذاری و محاسبات

- شماره سند: `<پیش‌شماره>-<سال شمسی>-<شماره ترتیبی چهاررقمی>` مانند `AG-1405-0001`
- مبلغ ردیف: `مقدار × قیمت واحد`
- جمع کالاها: مجموع مبالغ ردیف‌ها
- `مبلغ نهایی = جمع کالاها + هزینه حمل + مالیات − تخفیف`
- مالیات اختیاری است و از پایه `(جمع کالاها − تخفیف)` محاسبه می‌شود.
- مبالغ به نزدیک‌ترین عدد صحیح گرد می‌شوند و هرگز منفی نمی‌شوند.
- قیمت و مشخصات کالا در هر ردیف به‌صورت Snapshot ذخیره می‌شود؛ تغییر بعدی کاتالوگ، اسناد قبلی را تغییر نمی‌دهد.

## تاریخ شمسی

- ذخیره‌سازی در دیتابیس به میلادی (UTC) و نمایش/ورود به شمسی (`۱۴۰۵/۰۸/۲۸`).
- تبدیل‌ها در `lib/jalali.ts` و با تست واحد پوشش داده شده‌اند.
- پذیرش ارقام فارسی و نیم‌فاصله در ورودی تاریخ.

## داده نمایشی

داده‌های نمونه فقط برای محیط توسعه و با `SEED_DEMO=1` ساخته می‌شوند. در محیط عملیاتی seed را بدون این متغیر اجرا کنید تا فقط تنظیمات، دسته‌بندی‌ها و مدیر اولیه ایجاد شوند.

## وضعیت نسخه‌ها

- **فاز اول (تکمیل‌شده):** MVP شامل ورود، مشتریان، کالا، صدور پیش‌فاکتور، PDF، آرشیو، تنظیمات، کاربران، گزارش پایه و پشتیبان.
- **فاز دوم (آماده توسعه):** ارسال از طریق WhatsApp، یادآوری خودکار تاریخ اعتبار، گزارش‌های پیشرفته‌تر.
- **فاز سوم (آماده توسعه):** موجودی انبار، خرید و تأمین‌کننده، حواله خروج، مدیریت حمل، سود، حساب مشتریان. مدل داده با کلیدهای خارجی و نوع‌های قابل توسعه برای این بخش آماده است.

## نسخه ویندوزی — کاملاً آفلاین، با یک کلیک

سامانه یک برنامه دسکتاپ مستقل است: روی آیکون کلیک می‌کنید و باز می‌شود. کاربر نهایی نه
Node.js نصب می‌کند، نه PostgreSQL، نه Docker و **نه به اینترنت نیاز دارد**.

- تمام منابع محلی‌اند: فونت Vazirmatn داخل برنامه، آیکون و لوگو محلی، PDF با فونت
  جاسازی‌شده، دیتابیس PostgreSQL همراه و سرور Next.js روی `127.0.0.1`.
- در `desktop/main.cjs` تنها `127.0.0.1` مجاز است و هر درخواست بیرونی Chromium
  (`host-resolver-rules`) مسدود می‌شود؛ `NEXT_TELEMETRY_DISABLED` هم فعال است.
- دو خروجی ساخته می‌شود: `AghrinPishFactor-Setup-1.0.0.exe` (نصب معمولی) و
  `AghrinPishFactor-Portable-1.0.0.exe` (بدون نصب، فقط دوبار کلیک).

**ساخت (روی ویندوز):** دوبار کلیک روی `desktop\build-windows.bat` — یا `npm ci`،
`npm run build` و `npm run desktop:build`. خروجی در پوشه `release/` است.

**ساخت بدون ویندوز:** گردش‌کار `.github/workflows/windows-installer.yml` روی
`windows-latest` هر دو فایل را می‌سازد و به‌عنوان Artifact منتشر می‌کند.

- پوسته دسکتاپ: `desktop/main.cjs` (راه‌اندازی PostgreSQL همراه، اجرای migration، ساخت
  مدیر اولیه و اجرای سرور Next.js روی `127.0.0.1`)
- راهنمای کامل نصب، حالت آفلاین، محل داده‌ها، پشتیبان‌گیری و عیب‌یابی:
  [`docs/WINDOWS-INSTALL.md`](docs/WINDOWS-INSTALL.md)

> ساخت فایل `.exe` باید روی ویندوز انجام شود، چون باینری‌های PostgreSQL و موتور Prisma
> مخصوص ویندوز باید همراه بسته شوند.

## ارقام فارسی و سربرگ متفرقه

- همه اعداد رابط کاربری (مبالغ، تعداد، تاریخ، شماره سند، مقدار و قیمت در فرم‌ها) با ارقام
  فارسی نمایش داده می‌شوند. ورودی‌های عددی نیز ارقام فارسی را می‌پذیرند و در سرور
  نرمال‌سازی می‌شوند؛ مقدار ذخیره‌شده در دیتابیس همیشه لاتین و دقیق است.
- شناسه‌های فنی (نام کاربری، کد کالا، شماره موبایل، شناسه ملی) برای کپی‌کردن و جست‌وجو
  با ارقام لاتین نمایش داده می‌شوند.
- منوی «سربرگ متفرقه» یک برگ رسمی A4 برای مکاتبات غیر از پیش‌فاکتور چاپ می‌کند؛ لوگو و
  اطلاعات آن از «تنظیمات شرکت» خوانده می‌شود. سربرگ اصلی اختصاصی پیش‌فاکتور است.
